# 08 · 路线图

> 原则：**先验证最脆弱的假设，再做最想做的功能。**
> 每一期都必须有一个"能上手用"的交付物，不允许出现"写了三周还看不到东西"。

---

## 排期口径（2026-10-27 定）

**顺序 = 你的使用频率，不按工程难度排。**

```
1 大爆炸 → 2 一步 → 3 闪念胶囊 → 4 无限屏 → 5 拟物 App → 6 系统级拟物（可选）
```

这个顺序有一个代价，先说清楚：

> **大爆炸恰好是六项里技术风险最高的一个。** 它依赖"截屏 + 取字"这条链，
> 而截屏权限在国产 ROM 上不是必然给的。所以第 0 期体检必须先行——
> 体检结论直接决定大爆炸是"词级"还是"控件级"。

## 技术栈（已定）

| 项 | 选择 | 理由 |
|----|------|------|
| 语言 | Kotlin 2.x | 无障碍/悬浮窗/前台服务全是原生能力 |
| UI | Jetpack Compose | 拟物靠 Canvas + graphicsLayer，比 XML 自由 |
| minSdk | **30 (Android 11)** | `AccessibilityService.takeScreenshot()` 的下限 |
| targetSdk | 35 | 跟上 Android 15 的权限模型 |
| 架构 | 单 Activity + Navigation Compose | 悬浮层走 Service，不走 Activity |
| 存储 | Room | 胶囊、剪贴板、词库 |
| 图片 | Coil | — |
| OCR | RapidOCR / PaddleOCR(ncnn) | 离线、中文准、不依赖 GMS |
| 分词 | jieba-android | — |
| 语音 | sherpa-onnx（离线） | 第 3 期才用 |
| 模块 | **先单模块**，M2 后再拆 | 早期拆模块只增加配置成本；用 package 隔离 |

**为什么不用 Flutter / RN**：核心能力（无障碍、悬浮窗、截屏、前台服务）全在原生层，
跨平台框架最后还是要写原生插件，反而多一层。`fantasyao/shengwuji` 是 Dart 写的，读它的语音流程即可，不跟技术栈。

## 分期

### 第 0 期 · 体检（3 天）→ **M0**

**目标**：证明这台手机"能被改造成什么样"。**不写任何功能。**

交付物：
1. `probe/` —— 极简 APK，只做三件事：
   - 无障碍服务常驻，每 5 分钟往本地打点
   - 点按钮调 `takeScreenshot()`，显示成功/失败/耗时
   - 显示悬浮窗、无障碍、"受限设置"三个开关的实时状态
2. `docs/probe-report.md` —— 体检报告（截图 + 数据 + 结论）

**验收标准**
- 连续 24 小时，无障碍断线次数 **= 0**
- 截图成功率 **≥ 95%**，单帧 **< 800ms**
- 侧载 App 能走完"受限设置"打开无障碍

**决策点**
- 三条全过 → 大爆炸做**词级**（OCR）
- 截图不过、其余过 → 大爆炸做**控件级**（只炸节点树里的文字，图片里的字炸不了）
- 无障碍活不过 24h → 全盘降级为"桌面内闭环"，需要重新讨论方案

---

### 第 1 期 · 地基 + 大爆炸（4 周）→ **M1**

拆成三段，每段都有可见成果：

#### M1a · 地基（1 周）
- 拟物设计系统 v0：材质、单一光源、倒角、弹簧动效、拟物音效
- 触发层 v0：悬浮球 + 通知栏磁贴（两个入口，用户可关）
- 首次启动引导（体检五步）

**为什么先做地基**：大爆炸的"锤子味"全在这个词块层的手感和动效上，
没有设计系统，做出来就是个普通的文字选择器。

#### M1b · 大爆炸 v0（1 周）—— **第一次可用**
- 取字：只读无障碍节点树，不截图、不 OCR
- 词块：粒度 = **控件级**（微信里一条消息一块、浏览器里一段一块）
- 操作：点选多选、拖拽合并、复制/搜索/分享/全选
- 动效：炸开飞散 + 收招飞回 + 震动反馈

> **先把预期说清楚**：v0 的粒度是"一条一块"，不是"一个词一块"。
> 它已经能用了，但还不是原版那种"逐词炸开"。

**验收标准**
- 微信、浏览器、相册三个场景能炸出块
- 从触发到出块 **< 400ms**（不截图，纯节点树）
- 词块位置与原文字位置误差 **< 8dp**
- 收招后无残留、无闪烁

#### M1c · 大爆炸 v1（2 周）
- 截屏 + OCR 管线（节点树拿不到字的场景兜底）
- 行聚类 + 标点切分 + jieba 词级细分
- 混合策略：节点树优先，OCR 兜底

**验收标准**
- 相册里的图片文字能炸成**词级**
- 从触发到出块 **< 1.2s**（含 OCR）
- OCR 失败时自动降级到节点树，不弹错误

---

### 第 2 期 · 一步（3 周）→ **M2**

**目标**：只做"能做的 70%"，不硬啃跨应用拖拽。

交付物：
- 边缘热区 + 侧栏（应用 / 联系人 / 剪贴板历史 / 最近图片）
- 「存到一步」分享目标（`ACTION_SEND` / `ACTION_PROCESS_TEXT`）
- 侧栏 → 分屏/浮窗打开应用
- 剪贴板自动收纳
- 大爆炸的词块可以直接「存到一步」

**验收标准**
- 边缘内划 **150ms 内**出栏
- 任意 App 选中文字 → 分享 → 存到一步，**≤ 3 步**
- 侧栏拖应用到屏幕 → 正确进分屏

**明确不做**：从别的 App 里"随手拖出来"。系统不给第三方这个权限，不装。

---

### 第 3 期 · 闪念胶囊（2 周）→ **M3**

交付物：
- 唤起（长按音量下 / 磁贴 / 悬浮球三选一）
- 录音 + 实时波形 + 离线转写（sherpa-onnx）
- 胶囊时间轴、搜索、导出
- 胶囊可一键转待办、转一步

**开工前必读**：`fantasyao/shengwuji`（同类竞品，Apache-2.0），省试错。

**验收标准**
- 长按 → **300ms 内**胶囊升起
- 松手 → **2s 内**出文字（10 秒语音，离线）
- 连续 50 条不崩、不丢

---

### 第 4 期 · 无限屏（3 周）→ **M4**

**目标**：一个"可选桌面"，不是强制替换。

交付物：
- Launcher（`HOME` intent）+ 无限屏交互
- 手势唤起全局应用墙
- 陀螺仪视差 + 卡片 3D（Compose graphicsLayer）

**验收标准**
- 陀螺仪视差 60fps 无抖动
- 进入应用墙 **< 400ms**
- 随时能切回 Flyme 桌面

---

### 第 5 期 · 拟物 App（5 周，可与 2/3/4 期并行）

顺序（按你的使用频率可再调）：便签 → 时钟 → 计算器 → 录音机 → 天气

**验收标准**：单 App 资源 < 3MB、冷启动 < 500ms、深色模式完整、除天气外无网络权限。

原版 APK 移植作为彩蛋单独试，不占主线工期。

---

### 第 6 期 · 系统级拟物（可选，不排期）

root + RRO overlay + LSPosed。
先决条件：自愿解锁 BL（清空数据）并接受支付类 App 可能拒跑。
**不做也不影响前五期。**

```
M1c 大爆炸 v1       第 4 周     ← 词级炸开
M2  一步            第 7 周     ← 锤子两件套齐

M4  无限屏桌面      第 12 周

```

## 每期的固定动作

1. 开工前：写这一期的"验收标准"（可测的数字）
2. 收工时：真机回归，录屏存档到 `references/`
3. 每期结束更新 `docs/CURRENT.md`（当前能力边界、已知问题、下一步）
