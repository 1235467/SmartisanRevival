## 触发（v2，已在真机跑通）

锤子原版是 framework 在 `TextView` 长按里直接启动大爆炸。魅族在 Meizu 21 Pro / Flyme（Android 16）上，用 **Shizuku（shell 身份）直读 `/dev/input/event7` 的 evdev 二进制流**：

- 触摸设备：`main_touch`（`/dev/input/event7`），坐标范围 13680×31920（屏幕的 10 倍）
- **时间**：按住 ≥ 550ms，位移不超过约 40dp
- **面积**：用设置页那块区域按住，记下这个用户的 `TOUCH_MAJOR`。门槛 = 记下值的 78%。没校准前用 120（满量程 255），挡指尖轻点
- 无障碍树确认手指下面**有文字** → 炸该节点全文
- 按在按钮 / 空白 → **静默**，系统长按照常
- 每帧 `Log.i` 已关掉：打日志会拖住读线程，抬起事件晚到，轻点会被当成按住

上一版读 `getevent -ql` 的文本输出：管道里整块缓冲，实机读不到实时行，且 `DOWN`/`UP` 词形解析错。**已改为读二进制帧**（24 字节固定结构），这是唯一在本机跑通的方式。

**注入抬起（`input motionevent UP`）在这台机器上无效**：它走的是虚拟输入设备，无法取消原 App 已在进行的按压手势，已在 v2 移除，不再假装能顶掉菜单。

### 分段切法说明

备忘录常把整篇文字塞进**一个无障碍节点**（实测一篇 2376 字全在同一个 `EditText` 里，
bounds 却只覆盖屏幕上那 2313px）。所以：

- 按「每 10 行一组」切段，不依赖空行
- 按压点定位用**同窗口单行节点的高度中位数**折算行号，不能按 bounds 高度占比算
  （那个 bounds 是可见区域，不是全文高度）

## 重启手机之后（必看）

**重启后按压失灵是正常的，需要补两步：**

1. **Shizuku 服务端不会自动起。** 打开 Shizuku 应用重新激活（无线调试），或者
   插着 adb 跑一次：
   ```
   adb shell /data/app/~~kivBzam-e_JkXoxsi59BSA==/moe.shizuku.privileged.api-sv1ErzXxkgGcUHT7MuWJSg==/lib/arm64/libshizuku.so
   ```
   （`pm path moe.shizuku.privileged.api` 拿当前真实路径，路径里的随机串会变）
2. **Flyme 会重置无障碍开关。** 查：
   ```
   adb shell settings get secure enabled_accessibility_services
   ```
   为空就重新写回，或去设置里重开一次「大爆炸引擎」。

顺序很重要：**先让 Shizuku 就绪，再开无障碍**。反过来的话，无障碍服务连接时授权检查会失败。
v2 已加自动重试（每 3 秒一次，最多 40 次 ≈ 2 分钟），所以先开无障碍也能自己等到 Shizuku 起来。

重装 APK 也会触发一次无障碍重置，同样处理后即可。

**注意：Flyme 会自己把无障碍开关重置成 `null`。** 重装 / 重启后如果按压没反应，先查：

```
adb shell settings get secure enabled_accessibility_services
```

为空就用 `settings put secure` 重新写回，或去设置里重开一次。

**Shizuku 服务端重启后不会自动运行**，这是按压失灵最常见的原因。详见上一节。

## 炸图片（框选流，已跑通）

树里没字的按压不再整屏盲 OCR（实测按在图片上挑不到行，只会炸空面板），改为复刻
OS 8 TextBoom 的 `crop_image_ocr_view`：

- `ScreenCapture.take`（无障碍 `takeScreenshot`）冻结全屏 → `CropOverlayController`
  弹 `TYPE_ACCESSIBILITY_OVERLAY` 全屏层（窗口参数同一步侧栏 showPanel）
- `CropSelectView`：截屏做底、选区外压暗、蓝框 + 原版四角角标（从 TextBoom APK 提取）；
  标题栏 取消 | 框选需要识别的区域 | 识别文字；提示语原版「此区域不支持文字炸开…」
- 初始框 = `NodeTextExtractor.hitBoundsAtPoint` 命中的最小无字节点（图片就是它的框），
  接近全屏或没命中退回按压点居中 70%×45%
- 「识别文字」→ 选区裁剪 → `ScreenOcr.recognize`（本地 RapidOCR）→ 行坐标映射回屏幕 →
  `OcrTextExtractor.buildBangResult` → 炸面板；空结果 toast「未识别出文字」，界面留下可重划
- 实测（21 Pro）：手写便签图、日历数字均正确识别并分词；空选区/取消路径正常

**坑**：无障碍服务被重绑（开关变动、uiautomator dump 接管）会重建实例并丢弃旧窗口，
必须 onDestroy 里收干净覆盖层，否则残留孤儿窗口 + 状态卡死。另外取树在备忘录
